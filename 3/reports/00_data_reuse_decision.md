# Stage 2 数据复用决策

**选择 Option B（Reuse After Fixing）。** 两站的会话与小时计数均覆盖本地静态快照内的全部已列记录，可以直接作为 Stage 3 的只读输入。修复集中在 Stage 3 的来源与时间元数据、预测特征、切分和评分。当前没有证据要求改写会话起点或小时计数。Option C 的有限抽查已在本次审查中完成。

## Stage 3 需要生成的修订副本

1. 在 `3/data/processed/` 生成一份小型、带版本的小时视图。保留原小时键和计数，新增 `clock_basis`、边界小时和覆盖状态等最少必要字段。无外部证据的覆盖状态为 `unknown`，可同时记录是否观察到起点。单独保存来源路径、计数定义、输入 SHA-256 和证据等级。保留零值及峰值。旧的会话路径作为溯源字段保留，用配置定位指定原始根。
2. 条件性时间修订。现有 10 个样本的遥测为 UTC，文件名无时区且遥测首条有延迟。默认继续使用两站共同的源时钟。取得可信发布者说明或带时区 `connectionTime` 的会话对账后，才版本化映射到 UTC 和 `America/Los_Angeles`。若只需明确时区或重建日历特征，重新使用现有会话名或小时数据即可。对账发现实际时间不同且确需重新分桶时，使用已确认的会话起点重算受影响窗口。
3. 保存原一小时预测的回归对照，Stage 3 输出单列或单独版本的 `prediction_raw` 与 `prediction_nonnegative`。记录修复原因、验证结果与前后差异。多时域、跨站和 R² 使用新代码产生，原 Caltech MAE/RMSE 仅属于已知的 Stage 2 协议。

## 选择依据

Option A 足以再现历史一小时结果。目标时钟、数据质量语义、多跨度特征与跨站时间切分在后续需要调整，因此整体采用 Option B。Option C 补足了本次证据，也明确了样本所能回答的问题。两站均有完整的快照派生产出，现有证据不支持 Option D。
