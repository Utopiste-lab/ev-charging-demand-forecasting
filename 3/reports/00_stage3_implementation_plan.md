# Stage 3 实施方案

适用于两站的 1、3、6、24 小时直接预测和双向迁移。当前为 Phase 1，以下为下一阶段的工作清单、协议和验收条件。

## 1. 固定输入口径并建立一小时回归基准

- 用配置引用 Stage 2 顶层会话及小时表。读取原表，核对哈希、类型、唯一键、覆盖范围、全量逐小时对账和零区间。生成版本化的轻量小时视图与来源清单。按已记录会话开始数建模，默认源时钟、覆盖未知、计数保留原样。缺失小时与已存在的计数为零行需要不同状态，验证发现真正小时断档时停止并记录。
- 保留原 Caltech 1h 的 15,791/3,385/3,384 样本回归测试，先复现 MAE/RMSE 和原预测。保存原始预测及截断后的配对对照，比较 R²、负预测数、零值子组与非零子组。将源快照、预测语义和评估协议版本写入结果。可信证据触发时区或覆盖口径变更时，以新版本独立跑同一组键的对照并解释差异。
- 复用 `train_baselines.py` 的质量检查、评分和训练管道，在 Stage 3 中引入薄层配置、时序索引和模型工厂。让 `run_all.py` 明确工作模式、输出目录和配置哈希，禁止将 Stage 2 或原始路径用作输出。先跑一小时小型复现，再执行正式模型矩阵。

## 2. 定义 Direct Forecasting 的时间对齐

固定每小时前滚一次。令 `y[t]` 为目标起点 t 的 `[t,t+1h)` 计数，`o` 为发布时点，`h ∈ {1,3,6,24}` 为距目标区间结束的小时数。令 `Δ=1 小时`，目标起点为 `t=o+(h−1)×Δ`，目标结束为 `t+Δ=o+h×Δ`。以 10:00 发布为例，1h、3h、6h、24h 分别对应 10:00–11:00、12:00–13:00、15:00–16:00、次日 09:00–10:00。每个预测跨度单独拟合，标签为单个目标小时计数。

| 变量 | 可复用定义 |
|---|---|
| 日历 | 取目标起点 t 的小时、星期和周末，发布时已知。沿用固定 23+6+1 列。两站共用时钟口径和列顺序。 |
| 历史计数 | 取 `y[o−1h]`、`y[o−24h]`、`y[o−168h]`，均为已完成小时。按目标行实现时，对应偏移为 `h`、`h+23`、`h+167` 小时。 |
| 24 小时均值 | 对 `y[o−24h]` 至 `y[o−1h]` 共 24 点求均值。目标行实现为 `shift(h).rolling(24, min_periods=24)`。 |
| Seasonal Naive | 取 `y[t−24h]` 作为目标小时的 24 小时周期参考，所有当前 h 均满足参考小时结束 ≤ o，h=24 恰在 o 完成。 |

记录 `forecast_issued_at`、`target_hour`、`target_end`、`latest_history_hour` 与数据可用时延。默认假定上一小时在发布时到达。若确认上报延迟，按可用时间重建滞后，Seasonal Naive 必要时退到更早的同周期小时，并单独登记协议。历史间距在连续时间轴上计算。可信 UTC 映射可用时，保持 UTC 滞后并独立派生当地墙钟日历，特别验证 DST 的重复、跳过小时时间键。主基准周期固定为 24 实际小时。

验收用合成序列逐条查值，覆盖四个跨度、午夜与若适用的 DST，验证滚动窗口无当前未完成计数。更改任一发布时点之后的观测，既有特征和预测应不变。检查每行最新输入的观测结束时间、训练标签结束时间与发布时间。

## 3. 冻结同站切分与模型选择

- 原 Caltech 70/15/15 只作历史复现。正式同站实验在各站历史已就绪的**共同目标网格**上，对四个跨度统一去掉前 `168+23=191` 个目标小时作为预热，再按时间以 floor(0.70n) 和 floor(0.85n) 冻结目标期边界。各跨度使用相同测试目标，每个目标的发布时点随 h 变化。训练标签的区间结束须 ≤ 验证最早发布时点，验证用于选参的标签结束须 ≤ 测试最早发布时点。按最长跨度的最早发布时点统一裁剪训练、验证尾部，并登记被裁剪的边界行及实际比例。之前已完成且已到达的小时可作后续历史输入。正式一小时结果遵循[统一训练协议](03_unified_1h_revision.md)。在验证期选参后，各学习模型使用同一组可用的训练与验证标签重新拟合，再固定参数滚动预测。
- 按模型、站点与 h 独立选参，唯一主准则为验证 MAE。并列按预先规定的较简单候选及稳定顺序决胜。冻结候选、预处理、截断口径和目标窗口后，批量保存测试输出。原 Caltech 测试已被 Stage 2 检视，若新窗口重叠应披露。可在训练和验证时期内部补做小型前推验证，综合评估季节性和 2020 变化。
- 新 Stage 3 主表以非负预测比较四个模型，对输出统一取 `max(0,p)`。保留 raw 敏感性表和预测，不取整。统一用非负验证预测做选参，原一小时回归基准继续保留其 raw 选参协议。

| 模型 | 训练与验证设置 |
|---|---|
| Seasonal Naive | 固定 24 小时周期，无学习参数，用同一测试目标键。 |
| Ridge | 训练集拟合 `StandardScaler` 和 Ridge。初始网格 alpha=[0.1,1,10,100,1000,3000,10000]。上界再次胜出时记录，依据验证期预设扩展规则处理。 |
| Random Forest Regressor | 固定 `random_state=42` 和可控 `n_jobs`，初始 `n_estimators=300`，验证 `max_depth` 为 8、16 或 None，`min_samples_leaf` 为 2、8 或 24。树使用相同 34 列，无 scaler。 |
| Gradient Boosting Regressor | 固定 `random_state=42`，`loss='squared_error'`，初始验证 `n_estimators` 为 100、250，`learning_rate` 为 0.03、0.10，`max_depth` 为 2、3，`min_samples_leaf=10`。维持固定时序验证，关闭随机内部早停。 |

先做单站 1h 的树模型和两基线同协议对照，再批量跑两站 × 四模型 × 四时域。每个站点与时域保留相同的真实值、模型测试键与预测次数。记录训练耗时、样本量、划分、参数和库版本。

## 4. 双向迁移使用共同日历切分

共同可见小时范围为 2018-10-08 13:00 至 2020-12-02 23:00。建议冻结共用的目标日历边界为 2020-02-24 23:00 与 2020-07-15 00:00，沿用已知的 Stage 2 后期测试窗口，便于与旧结果对照。两站均从共同期并满足四跨度历史预热后建模。训练、验证按共同目标期与最长跨度最早发布时点裁剪，测试目标冻结至共同末小时。主跨站表按此共同日历，另以同窗口目标站自身历史训练的 in-site 模型作参考。任一方向均禁止源站未来标签、目标站 scaler 拟合、利用目标验证或测试真值选参。源站验证与目标站测试角色固定。两方向在同一测试目标日期，各表按实际目标站解释误差。

1. **目标站历史可用的迁移。** Caltech→JPL、JPL→Caltech 各遍历四模型和四时域。Ridge、RF、GBR 仅用源站训练/验证并冻结，预测时把输入替换成目标站截至 o 的历史计数与日历，单位保持会话/小时。Seasonal Naive 直接用目标站历史，其无需源站拟合的本地历史参照性质应注明。以同一目标和信息可用性对照同站训练版本，可计算迁移造成的误差差值。
2. **严格 zero-shot 补充实验。** 输入仅含已知目标日历。源站训练与验证整个流程不接触目标站历史，结果计算阶段才读目标标签。Ridge、RF、GBR 用源站日历特征重训。原 Seasonal Naive 依赖目标历史，该单元留 NA。可另报告只由源站训练段固定的星期×小时均值作为季节档案参照，空格回退到源站对应小时均值，再回退到源站全局均值。该参照单列，不沿用 Seasonal Naive 名称。两组结果独立呈现。冻结共同日历协议后保持匹配的测试键。
3. **验收。** 测试期间每个模型只拥有协议允许的历史。故意扰动目标站历史时，严格 zero-shot 预测应保持不变。校验源站所有参与拟合与选参的标签在第一条目标预测发布前已经结束，检查双向小时键、标签范围、配置和来源。

## 5. 分析与最终交付

- 每个条件报告 MAE、RMSE、R²、样本数、平均实际/预测、负预测比例及预测方案。R² 按 `1 − SSE/SST` 计算，常数目标或不足两个样本记 NA，允许负 R²。统一以每小时会话数作为 MAE、RMSE 单位。相同目标小时下报告相对 Seasonal Naive 的误差变化，分母为零时记 NA。跨站绝对误差结合站点需求水平和站内参照解读。
- 主实验保留零值。按月、零/非零和事后长零内外提供诊断，给出样本数和原口径指标。两站用共同日期对比分布、零比例、日内曲线与变化。报告各跨度性能、目标站与方向差异、过预测、Seasonal Naive 是否领先以及可能的解释。若提供误差区间，采用按天或周的时间块配对重采样，保持模型预测与目标成对。已有快照无法单独支持运营原因的推断。
- 布局为 `README.md`、`requirements.txt`、`run_all.py`、`config/`、`src/`、`data/processed/`、`experiments/01_baseline_and_ridge/` 至 `04_cross_site/`、`results/metrics/`、`results/tables/`、`results/figures/`、`reports/`、`logs/`。实验目录存配置或运行说明，统一结果目录存带 `run_id` 的逐行预测、验证表、指标表和图。图至少覆盖误差随跨度、双向迁移与两站分布变化。
- 编制中文和英文研究摘要，交付数据定义、实验口径、真实指标、已知不确定性和复现命令。固定经过实跑验证的依赖、种子和输出清单。核对所有实验键完整、指标可以仅用预测和真实值重算、历史阶段结果仍能复现。第一批可执行工作依次为质量与回归基准、Direct 共用索引、一小时树模型、全部时域、双向迁移和分析定稿。
